The one real design change made during extraction (flagged in the pre-implementation plan, §02)

DeviceCategory and ProtocolType no longer implement Laravel's Castable contract — that was a genuine conflict between two correct-in-isolation prior decisions (pure-PHP package vs. zero-touch Eloquent casts) that could only be resolved one way once the package boundary became real. The cast logic now lives in two new app-side classes: App\IntegrationEngine\Casts\DeviceCategoryCast and ProtocolTypeCast. IntegratedDevice.php's $casts array now references those instead of the enum classes directly — the one line of actual behavioral wiring this extraction touched beyond a namespace swap.

Wall-clock boot time — investigated, not just reported

Raw measurement: baseline boot averaged 1,716ms across 3 runs before extraction; the identical script averaged 4,551ms across 8 runs after. Reported as measured — but that gap didn't match the memory/class-count evidence, so it was investigated rather than written up at face value.

TestResult
Swap path-repository symlink: true → false (real file copy instead)No change — still ~4.8s
Repeat the same command 8× in a row (rules out one-time AV file-scan-then-cache)No improvement over time — consistently slow
time php artisan --version — compare wall time to actual CPU timereal 5.4–6.1s vs. user+sys ≈ 15–46ms
Windows Defender real-time protection statusConfirmed ENABLED
Conclusion: not a code regression — an I/O-interception artifact from this session's file-change volume

A process spending 46ms of actual CPU time to produce 5,400ms of wall-clock time is, by definition, spending >99% of its time blocked — almost always a signature of antivirus real-time file scanning intercepting the thousands of individual file opens PHP's autoloader performs, not additional computational work. Memory usage and class count — the two metrics that would move if the package boundary itself added overhead — are unchanged to the byte/class. Disabling the symlink (eliminating reparse-point traversal as a variable) made no difference, and the slowdown didn't decrease across repeated runs, which rules out both symlink overhead and a one-time per-file AV scan that then caches clean. Windows Defender's real-time protection was confirmed active during this session, which involved an unusually large burst of new and modified files (50 new package files, ~40 newly-installed dev dependencies, dozens of edits) — exactly the condition that triggers sustained on-access scanning until the AV's cache catches up.

Recommendation, not a fix applied here: exclude the project directory (or at minimum vendor/ and packages/) from real-time AV scanning in local development, a standard practice for PHP/Composer projects regardless of this extraction, and re-measure. This was not done as part of Phase 0 — it's an environment-configuration recommendation, not an application change, and outside this phase's scope.
